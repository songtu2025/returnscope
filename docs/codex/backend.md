# Codex Python、FastAPI 与 SQLite 规范

涉及 Python、FastAPI、后端接口、前后端 API 契约、SQLite、数据库或迁移时，必须读取本文件。

## 1. Python

生成或修改的 Python 代码必须：

1. 遵循 PEP 8，并使用 Ruff 格式化和检查。
2. 使用清晰的英文变量名、函数名、类名和文件名，不得使用拼音或无意义缩写。
3. 普通注释和 docstring 使用中文。
4. 公共函数和复杂业务逻辑必须有类型注解。
5. 使用项目选定的 Mypy 或 Pyright 进行类型检查。
6. 不得使用裸 `except`、吞掉异常或通过关闭 Ruff、类型检查规则掩盖问题。

## 2. FastAPI 分层

本项目后端基本依赖方向：

```text
API Router → Service → Database
```

职责约定：

- `web_backend/routers`：接收请求、校验参数、执行后端权限检查、调用服务并返回结果。
- `web_backend/api_contracts`：按业务域定义请求和响应结构。
- `web_backend/*_service.py`：处理业务规则、业务流程和内聚的数据访问。
- `web_backend/database.py`：管理 SQLite 连接、事务、基础结构和应用迁移记录。
- `web_backend/settings.py`、`security.py` 等模块：管理配置和安全能力。

FastAPI 路由只处理接口职责，不得堆积业务逻辑或大量数据库查询。只有在重复数据访问已经妨碍测试和维护时才提取 Repository，不得为套用分层模板创建空壳转发层。

## 3. 数据库与迁移

新增或变更持久化数据结构时，实施前必须核对：

1. 业务对象、对象关系、数据来源和唯一事实源；优先复用已有模型。
2. 受影响表和字段的业务含义、类型与精度，以及必要的主键、外键、唯一、非空和默认值约束。
3. 主要读写路径与索引的对应关系；不为尚无查询依据的字段预建索引。
4. 需要保证一致性的操作边界；涉及并发修改时，说明冲突处理方式。
5. 现有数据如何迁移、业务代码与数据库结构如何兼容，以及无法无损回滚时如何备份、恢复或补救。


涉及数据库时必须：

1. 保持现有 `sqlite3`、`app_migrations` 表和 `web_backend/database.py` 中的自定义迁移机制，不自动引入 SQLAlchemy 或 Alembic。
2. 每次结构变更必须有稳定迁移标识和校验信息，事务内执行，并提供升级、备份和可验证的回滚方案。
3. 明确受影响的表、字段、索引、数据量及兼容范围，保持 Schema、业务代码和迁移逻辑一致。
4. 迁移和生产数据搬运必须分别覆盖测试；涉及现有生产数据路径时复用 `web_backend/production_migration.py` 的受控流程。
5. 批量操作必须说明影响范围和回滚方式。

不得：

1. 直接修改生产数据库或手工修改生产表结构。
2. 擅自删除表、字段、索引或业务数据。
3. 擅自增加需求中没有的业务字段。
4. 未经确认增加系统字段、派生字段或管理字段。
5. 使用浮点数存储或计算金额。
6. 绕过 `app_migrations` 直接修改已部署数据库结构。
7. 自动执行生产数据库迁移。

生产数据库迁移只能由部署负责人执行。

## 4. API 契约

新增或修改接口契约时，实施前必须核对：

1. 接口对应的业务操作、调用方和服务方；路径、方法和命名遵循项目现有约定。
2. 请求、响应、字段校验、错误结果及权限要求；不得把数据库模型或内部字段直接当作对外契约。
3. 列表的分页、筛选和排序，以及写操作的幂等性和并发冲突处理；仅在业务场景需要时展开。
4. 已有调用方的兼容性；破坏性变更须说明迁移方式并获得确认。

客户端可指定页大小时，后端须确定页大小上限；可指定排序字段时，后端须限定允许的字段。具体范围依据业务与数据量确定，不套用统一数值。

错误契约须让调用方区分实际可能出现的参数错误、未认证、无权限、业务冲突和系统故障，并明确可展示的提示与后续操作；沿用项目已有的状态码和响应结构，不强制增加统一响应包装。对外错误不得暴露堆栈、SQL、内部实现或敏感数据。

已有认证的项目新增或变更接口时，须明确该接口是否允许匿名访问。匿名接口须说明开放范围和返回数据边界；不得因为前端未展示入口，就省略后端的访问控制。

同一业务数据存在列表、详情、统计或导出等多个入口时，须逐入口核对身份、权限和数据范围；有意不同的访问规则须在业务需求中明确。权限变更、敏感数据处理或关键业务状态变更时，实施前须判断是否需要审计；需要时记录操作者、操作、对象、时间和结果，不记录凭据或敏感载荷，不为未命中的场景新建审计设施。

涉及导入、导出、上传或下载时，须按实际功能核对权限、数据范围和失败处理；导入或上传还须核对允许的文件类型与大小限制。不涉及文件的接口不适用。

涉及导出时，须明确允许导出的字段；敏感字段按业务与权限要求决定不导出、脱敏或完整导出，不得直接把数据库模型的全部字段作为导出内容。

涉及文件下载时，须区分公开与私有文件；私有文件须在服务端或受控下载链接签发时核对身份、文件归属和权限，不得仅依赖前端按钮或难以猜测的 URL。公开文件不强制认证，但须确认其确实可以公开。

批量导入前须确认重复记录是拒绝、跳过还是覆盖，以及失败时是整体回滚还是保留成功项；结果须能区分成功和失败。规则未明确时不得自行选择覆盖或部分写入。

项目提供自动生成的 OpenAPI 文档时，新增或变更接口须核对文档中的路径、方法、请求和响应与实际契约一致；不要求在生产环境公开文档入口。

不适用的检查点说明理由，不得为了满足清单机械新增字段、接口、分层文件或版本号。

## 5. 定时任务（按需）

新增或修改定时任务时，须明确触发时间和时区、重复或并发执行的处理方式、失败后的重试或人工恢复方式，以及如何查看执行结果。不得为此默认引入调度平台或管理界面。
