# Codex React 与 JavaScript/JSX 工程规范

涉及 React、JavaScript/JSX、TypeScript 或前端业务逻辑时，必须读取本文件。界面规则由 `docs/web-ui-standard.md` 索引。

## 1. 项目基线

1. 前端位于 `web-prototype`，使用 React 19 函数组件和 Hooks、JavaScript/JSX、Vite。
2. 项目使用自定义 CSS 组件和绿色桌面驾驶舱主题，主要业务图标统一使用 `@phosphor-icons/react`，图表使用 Recharts。
3. 当前没有 Ant Design、TypeScript 或其他 UI 组件库。未经确认，不得因公司新项目基线迁移现有实现。
4. 视觉、交互、页面状态、响应式和可访问性要求只在 `docs/web-ui-standard.md` 及其三份专项规范维护。

## 2. React 与业务边界

生成或修改的前端代码必须：

1. 遵循现有 JavaScript/JSX、函数组件、Hooks、路由状态和样式组织方式；不得顺带改写为 TypeScript。
2. 使用清晰的英文变量名、函数名、组件名和文件名；普通注释和 JSDoc 使用中文。
3. API 请求放入现有 `shared/api`、Service 或等价数据访问层，复杂业务逻辑放入内聚的 Hook、Service 或业务模块。
4. 复用已有状态管理、业务组件和 `components/SharedUi.jsx` 等公共能力，不得在多处维护同一状态或复制已有组件。
5. 前端只负责展示和交互，不得代替后端权限校验；任务、复核、模型服务和存储清理权限以后端结果为准。
6. 页面、组件和 Hook 的职责及规模遵循 `docs/codex/code-quality.md`。

## 3. 组件决策

```text
现有组件或页面模式满足需求
└── 直接复用并保持交互一致

多个页面重复使用且包含稳定业务规则
└── 组合现有控件形成业务组件

现有能力无法满足必要的业务、交互或可访问性要求
└── 说明缺口、复用范围和验证方式后新增自定义组件
```

只改变名称、默认属性或样式时，不创建无业务价值的转发组件。新增自定义基础组件不得复制浏览器原生能力或已有公共组件，也不得依赖任意高优先级全局覆盖。

## 4. 禁止事项

1. 不得使用静默忽略、无约束动态类型或关闭检查规则来掩盖错误；后续引入 TypeScript 时同样不得滥用 `any`、`@ts-ignore` 或非空断言。
2. 不得把大量请求、状态、表单、弹窗和业务规则堆积在单个组件中。
3. 未经批准不得引入 Ant Design、新 UI 组件库、第二套图标库、CSS 框架、字体或可视化依赖。
4. 不得用 Emoji 代替业务图标，不得绕过 Phosphor Icons 建立第二套主要业务图标体系。
5. 不得为了视觉效果改变业务流程、字段、权限、默认值或操作结果。
