# 用户反馈语义分析智能体 Web 界面开发标准

- 规范基线：SEEKWAY Codex 开发规范 V1.8.1
- 来源提交：`181397ca1510db153f77695e820dcf1907062bb4`
- 适用范围：用户反馈语义分析智能体桌面 Web 系统；当前能力限于 Amazon 退货反馈
- 维护负责人：项目维护者
- 最后更新：2026-09-12

本文件保存所有界面任务都要遵守的核心规则，并索引按任务加载的专项规范。现有代码和已经确认的产品约束是项目事实，不因公司新项目默认值迁移技术栈或设计系统。

## 1. 项目配置

- 品牌名称：`SEEKWAY`。
- 产品形态：绿色、克制、信息密集的桌面运行驾驶舱。
- 前端技术：React 19、JavaScript/JSX、Vite。
- 组件体系：项目自定义 CSS 组件和 `web-prototype/src/components` 中的公共组件；不使用 Ant Design。
- 图标体系：`@phosphor-icons/react`，是唯一主要业务图标体系。
- 可视化体系：Recharts，仅用于业务图表。
- 默认语言：简体中文。
- 系统时间戳：后端使用 UTC。
- 业务源日期：保留源数据口径，不因系统时间戳口径自动转换。
- 前端显示时区：尚未形成统一转换策略；涉及跨时区展示的任务必须先明确目标时区、转换边界和显示格式。
- 主要设计视口：`1440 x 900`。
- 验证视口：`1024 x 640`、`1280 x 720`、`1440 x 900`、`1920 x 1080`，并检查浏览器 `125%`、`150%` 缩放。
- 最小支持宽度：`1024px`；不交付移动端导航和移动端专用流程。
- 设计来源：现有运行界面、`web-prototype/src/styles.css`、`web-prototype/src/styles` 和 `web-prototype/AGENTS.md`；不依赖 Figma。
- 权限事实：普通用户共享分析任务和人工复核；模型服务维护和存储清理只允许管理员操作。

## 2. 规则优先级

发生冲突时按以下顺序执行：

1. 用户明确提供的验收标准和设计要求。
2. 本项目填写后的界面规范及命中的专项规范。
3. `web-prototype/AGENTS.md` 中的产品约束。
4. 现有设计令牌、公共组件和相似页面模式。
5. SEEKWAY 公司规范的通用默认规则。

设计要求不得覆盖业务、权限、安全和可访问性要求。无法同时满足时，必须说明冲突、影响和可选方案后等待确认。

## 3. 专项规范路由

所有 Web 界面任务先读取本文件，再按任务内容读取下表中的专项规范。任务同时命中多项时全部读取，未命中时不加载。

| 任务内容 | 必须读取 |
| --- | --- |
| 页面骨架、桌面适配、应用壳层、登录页、导航或页面标题 | `docs/web-ui-layout-standard.md` |
| 按钮、表单、弹窗、抽屉、操作反馈或提交状态 | `docs/web-ui-form-standard.md` |
| 表格、列表、数据状态、数据格式、图标、图片或图表 | `docs/web-ui-data-standard.md` |

## 4. 设计原则

1. **任务优先**：第一屏优先展示当前任务、阻断、失败、需复核和可执行操作，不制作营销落地页。
2. **操作高效**：减少查找、录入、比较、恢复和批量处理步骤，保持高频操作位置稳定。
3. **层级清晰**：页面只保留一个主要标题，一个操作区域最多一个主按钮。
4. **密度适中**：数据页面保持紧凑但可读，长流程充分使用可用宽度和高度，不用短侧栏制造长期空白。
5. **状态完整**：覆盖加载、正常、空数据、筛选无结果、失败、无权限、冲突、禁用和操作反馈。
6. **语义一致**：任务、数据集、分类结果、复核批次和模型服务等对象在全站使用同一名称。
7. **减少装饰**：不使用无业务价值的大面积渐变、插画、玻璃拟态、超大标题、装饰卡片或空白。

## 5. 设计令牌与视觉基线

`web-prototype/src/styles.css` 顶层变量和 `web-prototype/src/styles` 中的职责化样式是当前令牌事实来源。新增样式必须复用现有语义变量，并放入职责匹配的样式文件；不得在全局样式和模块样式中重复维护同一选择器或令牌。

### 5.1 颜色

- 主色使用 `--green: #12765b`，深色状态使用 `--green-dark: #0d5d47`，浅色选中面使用 `--green-pale: #e8f4ef`。
- 主画布、面板、正文和次要文字分别使用 `--canvas`、`--panel`、`--ink`、`--muted`。
- 警告、失败和信息状态分别使用现有 `--amber`、`--red`、`--blue` 语义令牌及其浅色背景。
- 状态不能只靠颜色表达，必须同时提供文字、图标或形状。
- 正文与背景对比度不低于 `4.5:1`；控件边界、焦点和承载含义的图标不低于 `3:1`。

### 5.2 字体与数字

- 使用现有系统字体栈：Inter、Noto Sans SC、Microsoft YaHei 及系统回退字体，不增加远程字体。
- 页面标题、区块标题、正文和辅助文字沿用相似页面层级；业务正文和主要操作文字不得小于 `12px`。
- 表格数字启用等宽数字特性；长编号、哈希和代码使用项目现有等宽字体栈。
- 不只靠字号表达层级，还要结合间距、字重、分组和位置。

### 5.3 间距、尺寸与圆角

- 复用 `--desktop-page-padding: 24px`、`--desktop-section-gap: 16px`、`--desktop-field-gap: 8px` 等现有变量。
- 默认控件高度为 `36px`，紧凑控件为 `32px`；同一操作区的控件高度必须一致。
- 默认数据行高为 `44px`，复杂业务记录为 `80px`，表头为 `40px`。
- 普通控件沿用现有 `7px` 至 `9px` 圆角；只有既有内容卡片模式可使用 `12px`，不使用无语义胶囊形状。

### 5.4 层级、阴影与动效

- 默认通过背景和边框表达层级；`--shadow-sm` 用于既有内容卡片，`--shadow-lg` 只用于弹窗、抽屉等浮层。
- `z-index` 按应用壳层、顶部栏、弹窗和提示的现有层级维护，不使用任意超大数值。
- 普通过渡保持 `120ms` 至 `200ms`；动效不得阻塞操作或循环装饰，并支持 `prefers-reduced-motion`。

## 6. 可访问性

界面修改以 WCAG 2.2 AA 为验收目标；现有页面未经完整验证不得声明已经达到：

- 优先使用原生 `button`、`a`、`input`、`select`、`table` 等语义元素，不用 `div` 模拟交互控件。
- 所有关键功能可仅使用键盘完成，焦点顺序与视觉顺序一致，焦点清晰且不被固定区域遮挡。
- 表单标签、错误信息、图标按钮和动态反馈必须有可访问名称或关联关系。
- 自定义菜单、标签页、树、对话框和组合框遵循对应的 WAI-ARIA 键盘模型。
- 交互目标至少为 `24 x 24 CSS px`，常用桌面控件优先保持现有 `32px` 或 `36px` 高度。
- 页面缩放到 `200%` 后仍可阅读和操作；允许局部容器滚动，不得让文字或主操作不可达。

## 7. 工程与业务边界

- React、组件决策和依赖约束见 `docs/codex/frontend.md`，职责和复杂度见 `docs/codex/code-quality.md`。
- 不引入 Ant Design、第二套 UI 库、第二套图标体系、CSS 框架或新的可视化依赖。
- 不为视觉效果改变接口、字段、任务状态、分类规则、默认值、审计记录或权限。
- 前端隐藏操作不等于权限控制；管理员能力必须由后端再次校验并正确返回 `403`。
- 批量修改和人工复核必须保留操作者、时间、原值、新值、原因和版本冲突处理。

## 8. 界面验收清单

- [ ] 已读取本文件和任务命中的专项规范。
- [ ] 页面目标、信息层级和主操作明确，并复用现有令牌、组件和相似页面。
- [ ] 加载、正常、空数据、筛选无结果、失败、无权限、冲突、禁用和反馈状态按业务需要完整。
- [ ] 目标视口及 `125%`、`150%` 缩放下没有页面级意外横向滚动、遮挡或不可达操作。
- [ ] 表格需要横向滚动时只在表格容器内发生，关键标识和操作仍可使用。
- [ ] 关键路径可仅使用键盘完成，焦点、对比度、目标尺寸和语义结构符合 WCAG 2.2 AA。
- [ ] 主要图标来自 Phosphor Icons，图表来自 Recharts，没有混入第二套体系。
- [ ] 普通用户和管理员能力符合后端权限，不泄露无权限操作或敏感信息。
- [ ] 未擅自改变业务、接口、数据结构、技术栈或依赖。

未实际完成的视觉、交互或可访问性检查必须报告为“未验证”，不得凭代码推断通过。
