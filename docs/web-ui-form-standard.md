# 用户反馈语义分析智能体 Web 表单与反馈规范

本文件是 `docs/web-ui-standard.md` 的专项扩展。任务涉及按钮、表单、弹窗、抽屉、操作反馈或提交状态时必须读取。

## 1. 按钮与操作

- 一个操作区域最多一个主按钮，用于当前最重要且安全的下一步。
- 次要操作使用现有默认按钮或文字按钮，危险操作使用现有危险样式并与高频主操作保持距离。
- 按钮文案使用“动词 + 对象”，例如“创建任务”“保存配置”“发布复核结果”，避免只有“确定”或“处理”。
- 图标按钮使用 Phosphor Icons，并提供可访问名称和可见提示。
- 低频操作超过三个时收纳到现有“更多”菜单；批量操作始终显示影响数量和对象范围。
- 提交期间显示处理中状态并阻止重复提交，完成后提供明确成功或失败反馈。

## 2. 表单

- 每个控件必须有持久可见的标签，占位文本不能代替标签。
- 常规表单标签放在控件上方；紧凑筛选区可以使用统一宽度的左侧或内联标签。
- 同一表单中的控件高度、必填标识、帮助信息和错误位置保持一致，默认高度使用 `36px`，紧凑筛选使用 `32px`。
- 用户离开字段或提交时校验；错误信息必须说明问题和修复方式，并与字段建立程序关联。
- 单个字段失败不得清空其他有效输入；服务端返回冲突时必须保留用户草稿和最新服务端版本。
- 选项少且需要比较时使用单选或分段控件；选项多时使用可搜索选择器；立即生效的二元状态才使用开关。
- 日期、比例、数量、阈值和文件大小必须在标签、帮助或后缀中明确格式和单位。
- 长表单可使用吸底操作栏，但不得遮挡最后一个字段、错误信息或键盘焦点。

## 3. 任务、复核与配置约束

- 创建和修改任务必须展示数据版本、分类标准版本、模型选择及会影响结果的关键配置。
- 人工修改必须展示操作者、修改时间、原值、新值和修改原因；提交时带版本或修订号，冲突不能静默覆盖。
- 批量复核必须允许确认影响范围，并在执行后清楚区分成功、失败和未处理记录。
- 模型服务维护和存储清理只向管理员提供操作入口，并以后端 `403` 为最终权限判断。
- 普通用户共享任务与复核，不得用前端所有者判断阻止已授权的协作操作。
- 运行中的任务继续使用启动时配置快照；编辑共享配置不能让既有运行任务悄然改变。

## 4. 文件导入

- 文件选择后展示文件名、类型、大小和待导入对象，上传前说明支持格式与大小限制。
- 导入流程至少区分选择文件、检查中、可导入、存在问题、导入中、部分成功、成功和失败。
- 预检错误要定位到字段、工作表或记录范围；失败不得让用户误以为数据已经写入。
- 真实业务数据不得写入示例、日志、错误堆栈或前端持久缓存。

## 5. 反馈、弹窗与异常

- 立即完成的轻量结果使用现有 Toast；需要用户处理的异常保留在相关页面、表单或记录附近。
- 错误信息不得暴露堆栈、数据库细节、凭据或内部敏感路径；可以展示脱敏追踪编号。
- 弹窗只处理确认或短任务，复杂编辑使用独立页面或抽屉。
- 弹窗和抽屉打开后焦点进入容器，关闭后返回触发元素，并支持键盘关闭；有未保存内容时必须先确认。
- 删除、覆盖、停用、清理和发布必须说明对象、影响范围、版本变化和是否可恢复，按钮文案写明具体动作。
- 全页失败提供原因和重试路径；局部失败只影响对应区域，不清空其他成功内容。

## 6. 提交状态

每个提交操作至少覆盖默认、校验失败、提交中、提交成功和提交失败。按业务需要补充权限不足、版本冲突、部分成功、任务运行中和连接中断。

- 提交中按钮尺寸保持稳定，加载文字不得导致布局跳动。
- 成功反馈说明完成的对象和下一步；失败反馈引用具体对象和可执行的修复动作。
- 未知结果不能显示为成功；网络中断后必须通过服务端状态确认是否已经提交。

## 7. 表单验收

- [ ] 主次操作、危险操作和批量范围清晰，重复提交已阻止。
- [ ] 标签、帮助、错误和单位完整，键盘顺序与焦点恢复正确。
- [ ] 默认、校验失败、提交中、成功、失败、无权限和冲突状态按业务覆盖。
- [ ] 人工修改、批量复核和共享配置保留审计与版本校验。
- [ ] 管理员入口和后端权限一致，普通用户不能执行模型维护或存储清理。
