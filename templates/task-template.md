# SEEKWAY Codex 开发任务模板

使用者只需填写第 1 部分；不知道的内容可以直接写“不清楚”。Codex 必须通过提问完成第 2 至第 4 部分，并在非简单任务实施前获得确认。

## 1. 使用者描述

### 业务背景和当前做法

说明为什么要改，以及现在用什么工具、按什么步骤处理。

### 想解决的问题

说明哪里浪费时间、容易出错或无法完成。

### 期望结果

说明完成后希望看到的变化。

### 怎样算做成了

用业务语言描述可以接受的结果；不清楚时由 Codex 协助整理。

## 2. Codex 需求转换

- 任务级别：简单 / 标准 / 高风险，由 Codex 判定并说明理由。
- 现状流程 `As-Is`：由 Codex 整理。
- 必须保留的业务规则和硬约束：由 Codex 整理并确认。
- 现有工具限制、补救动作和可调整习惯：由 Codex 整理。
- 适合目标系统的流程 `To-Be`：由 Codex 提出并由用户确认。
- 目标、范围、不做事项和验收标准：由 Codex 整理并确认。

## 3. Codex 设计与计划

| 视角 | 结果 |
| --- | --- |
| 参与者、角色和职责 | 由 Codex 分析 |
| 业务流程、规则和异常 | 由 Codex 分析 |
| 用户旅程、操作和反馈 | 由 Codex 分析 |
| 领域对象、数据流和生命周期 | 由 Codex 分析 |
| 页面、导航、字段和页面状态 | 不适用 / 由 Codex 分析 |
| 前后端、接口、集成和失败边界 | 由 Codex 分析 |
| 安全、隐私、权限和审计 | 不适用 / 由 Codex 分析 |
| 性能、可用性、容量和兼容性 | 不适用 / 由 Codex 分析 |

- 验证策略：前端 Demo / 技术验证 / 直接实现，由 Codex 按最大不确定性建议。
- 允许修改范围：由 Codex 列出。
- 禁止修改范围：无 / 待确认。
- 数据库、认证、权限、配置、依赖和部署影响：由 Codex 分析。
- 新增生产依赖：本项目默认不允许；确有必要时必须单独确认，不因公司新项目基线自动增加。
- 风险、回滚和验证方案：由 Codex 说明。

### Web 界面影响

- 是否涉及界面：是 / 否。
- 设计来源：无 / Figma / 截图 / 现有相似页面 / 其他；无来源时复用现有规范和页面，不自行创造视觉方向。
- 目标视口和页面状态：继承 `docs/web-ui-standard.md`，仅填写本任务的例外和特殊业务状态。
- 是否需要移动端：默认否；如需要，必须明确目标视口和布局并单独确认。

## 4. PDCA 闭环

- 改造前基线：不适用 / 待填写。
- 目标和指标：不适用 / 待填写。
- 指标数据来源：不适用 / 待填写。
- 复查负责人和时间：不适用 / 待填写。
- 达标、未达标或出现副作用时的动作：保留 / 优化 / 回滚 / 暂停 / 下线 / 待确认。

配置中不得填写真实生产凭据。Codex 按 `AGENTS.md` 及任务命中的专项规范执行。
